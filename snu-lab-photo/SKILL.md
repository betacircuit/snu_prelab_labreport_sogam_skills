# 실험 사진 보정

사진은 측정 근거다. 원본을 읽고 보정은 별도 파일로 저장한다. 수치 판독과 계산은 원본 및 장비의 raw/CSV를 근거로 하며, 보정으로 새롭게 생긴 글자나 파형을 근거로 삼지 않는다.

## 처리 순서
1. 원본을 이미지 읽기 도구로 확인한다. 화면 전체, 채널 색/이름, 축·단위·배율, 측정값, 커서 값을 확인하고 판독 불가 영역을 적는다. 스크린샷에 computer-use 화살표·후광이 있으면 [LTspice 캡처 지침](../snu-circuit-lab/references/ltspice-computer-use.md)에 따라 다시 얻는다.
2. 실제 계측기 사진에는 아래 `scripts/enhance_scope.py`의 결정론적 픽셀 보정을 쓴다. 과도한 대비보다 약한 설정부터 적용한다. 생성형 채우기·글자 교체·파형 재그리기·AI 초해상도는 측정 근거 보정에 쓰지 않는다. 도구를 쓸 수 없으면 원본을 유지하고 가능한 범위를 밝힌다.
3. 화면 외곽이 기울었으면 관찰한 네 꼭짓점으로 원근만 바로잡는다. 밝은 반사는 낮은 강도의 조명 평탄화로 줄이고, 약한 대비/선명도 조정을 적용한다. 반사로 사라진 정보는 복구하지 못한다.
4. 원본과 보정본을 100% 크기로 나란히 확인한다. 소수점·부호·단위·커서·파형 극값/교차점·채널 색이 보존돼야 한다. 기존 숫자가 바뀌거나 윤곽이 이중으로 생기면 설정을 낮춰 다시 만든다. 원본의 판독 불가를 보정본만으로 확정하지 않는다.
5. 보고서에는 읽기 쉬운 보정본을 넣고 원본과 `.json` 처리 기록을 근거 폴더에 함께 둔다. **캡션과 본문에는 사진을 손본 내용(기울기·밝기 보정, 자르기, 회전)을 쓰지 않는다** — 캡션은 무엇을 잰 화면인지와 측정 설정만(예: `Fig.3 - Y 출력 상승 지연 (CH1 입력, CH2 출력, 80 ns/div)`). 빌드가 이런 말을 `[본인 글]`로 막는다. 전체 화면의 축/측정 목록은 유지하고 확대본은 별도 그림으로 만든다.

## 스크립트
Python의 Pillow·numpy를 사용한다. 실행 환경의 실제 Python 경로를 찾고 인자를 각각 넘긴다. 원본과 같은 경로 및 기존 출력 덮어쓰기를 거부한다.

```text
python scripts/enhance_scope.py original.jpg --output scope-clear.png --glare 0.15 --contrast 1.06 --sharpen 60
```

- `--screen "x1,y1;x2,y2;x3,y3;x4,y4"`: 원본 EXIF 방향을 바로잡은 화면의 **좌상→우상→우하→좌하** 네 점. 화면 전체의 실제 경계를 보고 지정한다. 자동 추측하지 않는다.
- `--crop x,y,width,height`: 부가 확대본에만 사용. 화면 전체/측정 목록을 보존한 본 그림도 제공한다. `--screen`과 동시에 쓰지 않는다.
- `--glare 0..0.3`: 완만한 밝기 불균일 완화. 반사된 사람/방의 형태나 포화된 흰 영역을 지우는 기능은 아니다. 기본 0.15.
- `--contrast 0.9..1.2`, `--sharpen 0..100`: 약한 대비 및 선명도. 채널 색을 흑백으로 바꾸지 않는다. 배율 확대나 숫자 재합성은 하지 않는다.
- `--glare 0 --contrast 1 --sharpen 0`: 기하 보정만 적용하거나 그대로 저장하는 비교 기준.

## 보정으로 해결되지 않는 경우
장비에서 PNG/USB 화면 저장이 가능하면 그것을 우선한다. 반사가 파형이나 숫자를 가리면 기기 raw/CSV 또는 재촬영을 사용한다. 재촬영은 화면을 닦고 정면에 가깝게 두되 반사되는 조명/촬영자를 비켜서, 플래시 없이 화면이 과노출되지 않게 한다. 사진에서 사라진 정보를 채워 넣어 보고서를 완성하지 않는다.
