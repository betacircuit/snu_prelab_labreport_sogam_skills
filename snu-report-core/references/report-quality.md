# 보고서 내용 기준

서식은 format.md, 문체는 writing.md, 근거는 evidence.md가 원본이다. 여기는 내용 판단만 적는다.

## 원문과 답변
- 과목, 수업 실험 번호, 교재 실험 번호를 따로 확인한다. 교재 10번이 수업 1번이면 제목은 1, 본문 문항은 교재 원래 번호다.
- 원문 문항을 `requirements.md`에 요약하고 `requirements.yaml`에 범위·원문 위치·답변 제목·근거 파일·상태를 적는다 (`templates/requirements.example.yaml`). `scope`가 provisional이면 완성본이 아니다.
- 회이실은 교재 문항 순서대로 답하고, 논설실의 목표·요약·고찰 틀을 쓰지 않는다.
- 문항 하나의 답: 결론·결과 → 식·수치·그림 근거 → 필요한 해석. 기호 정의, 모델 조건, 단위, 대입·결과가 그 자리에서 이해돼야 한다.
- 분량을 맞추려고 풀이를 빼거나, 같은 이론·표·불확실성 설명을 문항마다 되풀이하지 않는다. 이미 보인 내용은 "@tbl:x의 값"처럼 가리킨다.

## 측정과 해석
- 사진을 배정할 때 회로·조건·채널·프로브 배율·표시 단위를 확인한다. 주파수가 같다고 회로를 단정하지 않는다. 후보를 다 본 뒤 중복·다른 조건·미식별 자료를 가른다.
- `Vamp`, `Vpp`, RMS, 자동 Delay, 커서 Δt는 서로 다른 값이다. 장비 정의와 입력/출력 대응이 확정된 것만 이득·위상·오차율로 해석한다.
- 애매하면 확실히 읽히는 값까지만 쓴다. 채널을 뒤집거나 이론값으로 빈 측정을 채워 오차를 만들지 않는다.
- 회이실 시뮬레이션 캡처가 필수이면 실제 LTspice 화면이 필요하다. ngspice·이상적 op-amp 계산을 실소자 시뮬레이션 완료로 치지 않는다.
- 오차율은 기준값과 부호/절댓값 정의를 적는다.
- 사용자가 미측정·미수행을 확인했으면 그 사실을 평서문으로 쓴다.
