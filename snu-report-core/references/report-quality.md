# 보고서 품질 기준

## 원문과 답변

- 과목·수업 실험 번호·교재 실험 번호를 각각 확인한다. 교재 번호가 10이고 수업 번호가 1이면 제목은 수업 번호 1, 본문 문항은 교재의 원래 번호다. 과목명에 실험 번호를 덧붙이지 않는다.
- 원문 문항을 읽고 `requirements.md`에 요약한 뒤, `requirements.yaml`에 종류별 확정 범위·원문 위치·답변 제목·근거 파일·답변 상태를 기록한다. 형식은 `templates/requirements.example.yaml`. 파일이 없거나 `scope`가 provisional이면 완성본으로 표시하지 않는다.
- 회이실은 교재 문항 순서를 지키면서 Claude 원본과 같은 자동 절 번호 `1.` → `1.1)` → `1.1.1)`를 쓴다. 원문 문항 번호는 함께 보존한다. 원문에 없는 `가)·나)·다)`를 만들지 않으며, 논설실의 목표·요약·고찰 틀은 적용하지 않는다.
- 요구 문항 하나의 답은 결론/결과 → 식·수치·그림 근거 → 필요한 해석으로 잇는다. 분량이나 문단 수를 맞추기 위해 풀이 단계를 빼거나 같은 이론 표를 반복하지 않는다. 식은 기호 정의, 모델 조건, 단위, 대입·결과가 독립적으로 이해되어야 한다.

## 측정과 해석

- 사진을 배정할 때 회로·조건·채널 대응·실제 프로브 배율·장비 표시 단위를 확인한다. 주파수가 같다는 이유만으로 회로 종류를 확정하지 않는다. 모든 사진 후보를 확인한 뒤 중복·다른 조건·미식별 자료를 구분한다.
- 화면의 `Vamp`, `Vpp`, RMS, 자동 Delay와 커서 Δt는 같은 값이 아니다. 장비 정의와 입력/출력 대응이 확정된 측정만 이득·위상·오차율로 해석한다.
- 모호한 경우 확실히 읽히는 채널 간 값까지만 쓴다. 불확실성은 최초 설명 한 곳에 모으고 각 문항에서는 그 결론을 참조한다. 채널을 뒤집거나 이론값으로 빈 측정을 채워 오차를 만들지 않는다.
- 회이실의 시뮬레이션 캡처가 필수이면 실제 LTspice 화면이 필요하다. ngspice·이상적 op-amp 계산 검증을 실소자 모델 시뮬레이션의 완료로 표시하지 않는다. 계산으로 추가한 검증은 요구 문항 안에 필요한 만큼만 넣는다.
- 원시 정밀도로 계산하고 마지막에 표시 자릿수로 반올림한다. 표의 반올림 값으로 계산해야 하는 과제 지시가 있을 때만 예외를 명시한다. 오차율은 기준값과 부호/절댓값 정의를 적는다.

## 페이지와 그림

- 원고가 시작되기 전 독립 표지를 추가하지 않는다. 기존 글꼴·흑백·캡션 틀 등 사용자가 정한 서식은 유지한다.
- 장비 사진의 숫자·축·단위는 문서의 실제 표시 크기에서 읽혀야 한다. 필요한 경우 원본을 보존한 별도 crop/확대본을 만들고 문맥을 잃지 않게 배치한다. 기전연 코드·결과 캡처는 컬러 그대로 유지한다.
- 세로로 긴 그림은 폭만 맞추지 않는다. 그림+캡션이 사용 가능한 쪽 높이를 넘으면 비율을 유지해 줄이고, 글자가 작아지면 여러 세부 그림으로 나눈다. 제목과 그 아래의 설명/식이 다른 쪽으로 갈라지지 않는지 확인한다.
- 누락 사진 자리는 초안에만 한 줄 표시로 둔다. 반복 파일명·촬영 지시·빈 프레임을 그림으로 넣어 한 쪽씩 차지하지 않는다. 최종본에는 누락 표시가 없어야 한다. 사용자가 미측정/미수행을 확인한 경우에는 사실을 평서문으로 쓴다.
- 그림 틀과 표의 글자 크기는 공통 format.md의 Claude 원본 양식을 따른다. 숫자 표에는 충분한 셀 여백을 둔다. 큰 그림 뒤로 도입 설명·수식·비교 문단이 흩어지면 문항 안의 배치를 다시 잡는다.
- 독립 수식은 가운데 정렬하고 분수·근호·첨자가 잘리지 않는지 확인한다. `CH2−CH1`의 가로 첨자와 `10⁻⁶`의 음수 지수도 별도로 본다. 수식이 폭을 넘으면 여러 식으로 나눈다. 그림+캡션 뒤에는 실제 빈 문단(Enter)이 정확히 하나 있어야 한다.
- computer-use 포인터·클릭 후광·툴팁·메뉴가 파형이나 측정값을 가린 캡처는 다시 얻는다. 오실로스코프 사진 보정은 `snu-lab-photo`를 사용해 원본과 나란히 확인한다. 보정본에서 새로 생긴 숫자/파형은 측정 근거가 아니다.
- 페이지 수 목표를 임의로 정하지 않는다. 내용이 짧은 마지막 쪽, 연속된 큰 여백, 제목만 남는 쪽, 표/그림과 캡션 분리를 보고 수정한다. `quality.py` 자동 검사는 일부 구조 오류만 잡으므로 실제 렌더링 검토를 대신하지 못한다.

## 완료 판정

`build.py` 성공은 초안 생성 완료다. 최종본 전달은 원문 대응·본문/OOXML 검사·최신 렌더링·모든 쪽 시각 검토를 거쳐 `quality.py deliver`가 성공했을 때다. 검토는 DOCX와 쪽 이미지의 해시로 연결된다. 렌더링 뒤 Word에서 한 글자라도 수정하면 다시 렌더링하고 검토한다. 소스 파일의 실제 내용과 답변 적합성은 작성자가 읽어 검증한다. YAML 상태만 answered로 바꾸어 검증을 대신하지 않는다.
