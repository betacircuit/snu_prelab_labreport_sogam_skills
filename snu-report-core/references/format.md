# 서식 규칙

사용자의 현재 지시와 명시적인 참조 양식이 가장 우선이다. 아래는 저장된 기본값이며, 사용자가 서식 개선을 요청하면 실제 쪽의 문제를 고쳐 기본값도 갱신한다. 과거 문서의 실수·빈칸·중복 번호를 원하는 양식으로 간주하지 않는다.
대부분은 `build.py`·`docx_post.py`가 자동으로 적용하고, "원고"라고 적힌 것은 원고를 쓸 때 지킨다.

## 파일
| 항목 | 규칙 | 적용 |
|---|---|---|
| 전달 형식 | `.docx`만 전달한다. PDF는 내 확인용 미리보기 | build.py |
| 파일 이름 | `prelab01_학번_이름` / `lab01_학번_이름` (예: `prelab01_2025-12345_홍길동`) (소문자, 두 자리 번호) | build.py (고정) |

## 첫 쪽
표지 없이 첫 쪽 위에 가운데 정렬 제목 블록을 둔다.
```
              논리설계 및 실험                     ← 굵게, 16 pt (두 줄)
              실험 1 결과보고서                    ← 굵게, 16 pt
      측정 장비 사용법 및 논리 게이트의 이해          ← 부제, 13 pt, 보통 굵기
   7조    2025-12345 홍길동    (조원: 김철수, 이영희)
              실험일: 2026년 9월 22일
```
prelab은 `실험 N 예비보고서`, 정보 줄은 `7조    2025-12345 홍길동` 한 줄. 조원이나 조가 비어 있으면 그 부분을 뺀 줄을 쓴다. 모두 style.yaml `title_block`에서 바꾼다.

## 글자와 문단
| 항목 | 규칙 | 적용 |
|---|---|---|
| 글꼴 | 제목·본문, 한글·영문 모두 맑은 고딕 (수식만 Cambria Math) | style.yaml |
| 굵게 | 맨 위 제목과 절 제목(`1.`, `1.1)`)에만. 본문, 목록 이름표, 캡션, 부제·정보 줄은 보통 굵기 | style.yaml, style_check.py |
| 색 | 제목·본문·수식·링크·표·캡션·쪽 번호의 글자는 명시적 `000000`. 테마 색, 직접 서식, 상속된 Hyperlink 색도 제거한다. 실제 측정/시뮬레이션 사진의 픽셀 색은 보존 | docx_post.py, style.yaml |
| 절 번호 | `1.` → `1.1)` → `1.1.1)`을 제목마다 한 번만 표시한다. `2.3) 3) 120 nF`는 `2.3) 120 nF`로 만든다. 자동 절 번호를 붙이기 전 원고 제목 앞의 기존 번호를 제거하며, `120 nF`·`3-bit` 같은 내용은 보존한다. 교재 문항 번호는 원고와 `requirements.yaml` 대응표에 보존하고 출력 제목에 겹쳐 붙이지 않는다. 번호 없는 제목과 자동 번호를 끈 양식은 유지한다 | course.yaml, build.py, quality.py |
| 문단 시작 | 본문 문단 첫머리에 공백 한 칸 | docx_post.py |
| 한글-영문 간격 | Word의 한글-영문·숫자 자동 간격을 끈다 ("7 조" → "7조", 한글(HWP)과 같게) | docx_post.py |
| Enter | 사진·캡션 뒤에는 실제 빈 문단(Enter)을 정확히 하나 둔다. 전용 `Figure Spacer` 문단은 정리 단계에서 지우지 않는다. 그 외 불필요한 빈 문단 반복은 없애고, 본문은 문단 뒤 6 pt·줄 간격 1.35로 통일한다 | docx_post.py |
| 줄바꿈 | `B = 1` 같은 짧은 식과 `10 ns` 같은 숫자·단위는 줄 끝에서 나누지 않는다 | build.py |
| 목록 | 번호 목록 `1. 2. 3.`, 글머리 기호 `-` (들여쓰기 얕게) | docx_post.py |
| 목록 항목 | 항목 머리에 이름표 + 쌍점 (굵게 하지 않음): `- $B = 0$일 때: …`, `1. 회로 연결: …` | 원고 |

## 표
| 항목 | 규칙 | 적용 |
|---|---|---|
| 선 | 모든 칸 구분선 (격자) | make_template.py |
| 칸 | Claude 원본의 10 pt, 가운데, 줄 간격 1.0, 머리행 보통 굵기·음영 없음. 사방 5 pt 여백, 행 높이는 자동으로 늘어나며 긴 표의 머리행은 반복 | docx_post.py |
| 캡션 | 표 맨 아래 행을 전체 병합해 `Table.1 - 캡션` (보통 굵기, 가운데) | docx_post.py |
| 머리행 | 짧게 쓴다 (`B`, `구분`, `1회`, `평균`, `계산값`). 너비가 모자라면 공백·괄호 앞에서만 줄바꿈 | 원고 + autofit |
| 숫자 | 같은 표 안에서 소수 자릿수를 맞춘다 (`30`과 `43.6`이 같이 있으면 `30.0`) | 원고 |
| 단위 | 모든 열이 같으면 캡션에 `(단위: ns)`. 서로 다른 측정량이면 각 머리행에 단위를 쓰고 캡션에 반복하지 않는다 | 원고 |

## 쪽 배치
- 문항마다 답변 → 필요한 근거 그림/식 → 해석이 이어지게 쓴다. 제목만 앞 쪽 끝에 남기거나 "전달함수는 다음과 같다" 뒤의 식을 다음 쪽으로 넘기지 않는다.
- 그림은 가로 140 mm·세로 95 mm, 세로형(높이/폭 ≥ 1.25)은 높이 80 mm가 기본 상한이다. 원고의 `width=100%`도 이 상한을 넘을 수 없다. 비율을 유지하고 원본이 작으면 확대하지 않는다. 축·숫자가 읽히지 않으면 작은 그림으로 우기지 말고 핵심 화면의 세부 그림이나 별도 판독 표를 함께 배치한다. 사용자가 다른 상한을 지정하면 설정을 갱신한다.
- 모든 그림에 `width=95%`를 복사하지 않는다. 보드 사진은 배선이 보이는 크기, 회로도는 소자명과 값이 읽히는 크기, 스코프는 화면 수치가 읽히는 크기로 각각 잡는다. 측정 결과와 짧은 위상 계산은 근거 사진 앞에 묶고, 사진 아래에는 그 결과의 해석을 둔다.
- 누락 그림은 초안의 한 줄 표시로 남긴다. 빈 사진 프레임·가짜 스크린샷·내부 파일명·촬영 지시를 큰 그림으로 넣지 않는다. 자료 요청과 작업 메모는 채팅/근거표에 둔다.
- 초안의 한 줄 누락 표시는 해당 설명이나 계산 표와 같은 쪽에 붙인다. 다음 쪽 첫 줄에 누락 표시만 남기지 않는다.
- 표가 길면 쪽을 나누고 머리행을 반복한다. 모든 셀에 keepNext를 걸어 표 전체가 다음 쪽으로 밀려나는 것을 피한다.
- 캡션의 keepNext는 명시적으로 false로 지정한다. 설정을 생략하면 Word의 캡션 스타일에서 true를 상속해 다음 문항까지 붙잡고 큰 빈칸을 만들 수 있다.
- 쪽 수를 맞추는 수동 페이지 나누기부터 넣지 않는다. 그림 크기, 문단 순서, 표 폭을 먼저 고치고 다시 렌더링한다. 마지막 쪽의 그림 하나·두세 줄만 남는 배치는 앞 쪽과 함께 조정한다.
- 별도 검증 표가 앞의 이론 표와 같은 숫자만 반복하면 제거하고 검증 방법·차이만 원래 문항에 합친다. 문항 자체나 필요한 풀이를 빼서 분량을 줄이지 않는다.

## 수식
| 항목 | 규칙 | 적용 |
|---|---|---|
| 형식 | 기호와 계산은 전부 Word 수식 (`$Y_1$`, `$t_{PLH}$`). Word에서 바로 편집할 수 있다 | pandoc |
| 정렬 | 독립 수식(`$$…$$`)은 문단 정렬과 OMML 정렬을 모두 가운데로 지정한다. 문장 속 짧은 기호는 본문 흐름을 유지한다 | math_layout.py |
| 첨자 | `CH2−CH1`, `−6`처럼 여러 조각으로 변환된 첨자·지수는 투명한 OMML 묶음으로 감싼다. 글자·부호·서식을 합치거나 수식을 이미지로 바꾸지 않는다. 브라우저 DOCX 미리보기에서도 가로 배치와 음수 부호를 확인한다 | math_layout.py |
| 세로 공간 | 독립 수식 앞뒤 8 pt, 자동 줄 높이 1.25. 고정 줄 높이·격자 맞춤·고정 표 행 높이를 쓰지 않는다. 분수, 적분, 근호, 위아래 첨자가 필요한 만큼 높이를 늘리고 식 한 덩어리를 쪽 사이에서 나누지 않는다 | math_layout.py |
| 결과 | 계산한 값은 식과 결과를 한 수식에 쓴다: `$t_{PHL} - t_{PLH} = 13.1 - 12.3 = 0.8\ \text{ns}$` | 원고 |
| 기호식 | 새 공식은 기호식 → 대입 → 결과 순서로 쓴다. 본문 폭에 여유 있게 들어갈 때만 한 줄에 두고, 긴 식은 일반식과 대입·결과를 나눈다 | 원고 |
| 공백 | `=`, `+`, `−`, `×`, `≈` 양옆과 단위 앞에 공백 | build.py (자동) |
| 곱셈 | `2 \times 13.1` (괄호 `2(13.1)`은 쓰지 않는다) | 원고 |
| 긴 식 | 분수·괄호 나눗셈·긴 식은 문장 중간에 두지 않고 따로 한 줄(`$$…$$`)로 뺀다. 숫자 대입까지 한 줄에 넣으면 여백을 넘는 식은 일반식과 대입·결과를 두 줄로 나눈다. 배치 방법은 writing.md | 원고, proof.py `[수식]` |
| 세움꼴 | 변수만 기울임. 단위(`V/m`, `F/m`)와 함수 이름(`sin`, `sinh`, `sinc`)은 세운다 | build.py (숫자 뒤 단위·함수 이름 자동) |
| 크기 | 문장 속 수식 10 pt, 따로 뺀 수식 11 pt (Cambria Math가 같은 pt의 본문보다 커 보여서) | style.yaml `size.math`, docx_post.py |

수식이 공간에 안 맞으면 글자를 축소하거나 첨자를 세로로 쌓지 않는다. 일반식 → 대입 → 결과를 의미가 유지되는 여러 독립 수식으로 나누고 다시 렌더링한다. `quality.py check`는 정렬·고정 높이·추정 폭 오류를 최종 전달에서 차단한다. 폭 추정만으로 잘림을 보증할 수 없으므로 모든 수식의 분수선·괄호·첨자·양끝 기호를 실제 페이지에서 확인한다. Word/PDF와 앱의 DOCX 미리보기가 다르면 어느 뷰어에서 발생하는지 구분하고, 한쪽의 정상 표시만으로 모두 정상이라고 말하지 않는다.

## 참고문헌
가이드북 말고 따로 인용한 외부 자료(별도 datasheet, 교재, 논문)가 있을 때만 절을 만든다.
가이드북만 참고했다면 참고문헌 절을 넣지 않는다.
