# 서식 규칙

사용자의 지시와 참조 양식이 우선이고, 아래는 저장된 기본값이다. 서식 개선 요청을 받으면 실제 쪽을 고치고 기본값도 갱신한다. 대부분 `build.py`·`docx_post.py`가 적용하고, "원고"라고 적힌 것만 쓸 때 지킨다.

## 첫 쪽
표지 없이 첫 쪽 위에 가운데 정렬 제목 블록을 둔다.
```
              논리설계 및 실험                     ← 굵게, 16 pt (두 줄)
              실험 1 결과보고서                    ← 굵게, 16 pt
      측정 장비 사용법 및 논리 게이트의 이해          ← 부제, 13 pt, 보통 굵기
   7조    2025-12345 홍길동    (조원: 김철수, 이영희)
              실험일: 2026년 9월 22일
```
prelab은 `실험 N 예비보고서`, 정보 줄은 `7조    2025-12345 홍길동` 한 줄. 조원이나 조가 비어 있으면 그 부분을 뺀 줄을 쓴다. 모두 style.yaml `title_block`에서 바꾼다.

## 글자와 문단
| 항목 | 규칙 | 적용 |
|---|---|---|
| 글꼴 | 제목·본문, 한글·영문 모두 맑은 고딕 (수식만 Cambria Math) | style.yaml |
| 굵게 | 맨 위 제목과 절 제목(`1.`, `1.1)`)에만. 본문, 목록 이름표, 캡션, 부제·정보 줄은 보통 굵기 | style.yaml, style_check.py |
| 색 | 제목·본문·수식·링크·표·캡션·쪽 번호의 글자는 명시적 `000000`. 테마 색, 직접 서식, 상속된 Hyperlink 색도 제거한다. 실제 측정/시뮬레이션 사진의 픽셀 색은 보존 | docx_post.py, style.yaml |
| 절 번호 | `1.` → `1.1)` → `1.1.1)`을 제목마다 한 번만 (`2.3) 3) 120 nF` → `2.3) 120 nF`). 원고 제목 앞의 원문 번호는 지우고 대응표에만 남긴다. 원문에 없는 `가)·나)·다)`는 만들지 않는다 | build.py, quality.py |
| 문단 시작 | 본문 문단 첫머리에 공백 한 칸 | docx_post.py |
| 한글-영문 간격 | Word의 한글-영문·숫자 자동 간격을 끈다 ("7 조" → "7조", 한글(HWP)과 같게) | docx_post.py |
| 문단 간격 | 문단 뒤 6 pt, 줄 간격 1.35. 빈 문단은 그림 뒤 하나만 (아래 "그림") | docx_post.py |
| 줄바꿈 | `B = 1` 같은 짧은 식과 `10 ns` 같은 숫자·단위는 줄 끝에서 나누지 않는다 | build.py |
| 목록 | 번호 목록 `1. 2. 3.`, 글머리 기호 `-` (들여쓰기 얕게) | docx_post.py |
| 목록 항목 | 항목 머리에 이름표 + 쌍점 (굵게 하지 않음): `- $B = 0$일 때: …`, `1. 회로 연결: …` | 원고 |

## 표
| 항목 | 규칙 | 적용 |
|---|---|---|
| 선 | 모든 칸 구분선 (격자) | make_template.py |
| 칸 | 10 pt, 가운데, 줄 간격 1.0, 머리행 보통 굵기·음영 없음, 사방 5 pt 여백, 긴 표는 머리행 반복 | docx_post.py |
| 캡션 | 표 맨 아래 행을 전체 병합해 `Table.1 - 캡션` (보통 굵기, 가운데) | docx_post.py |
| 머리행 | 짧게 쓴다 (`B`, `구분`, `1회`, `평균`, `계산값`). 너비가 모자라면 공백·괄호 앞에서만 줄바꿈 | 원고 + autofit |
| 숫자 | 같은 표 안에서 소수 자릿수를 맞춘다 (`30`과 `43.6`이 같이 있으면 `30.0`) | 원고 |
| 단위 | 모든 열이 같으면 캡션에 `(단위: ns)`. 서로 다른 측정량이면 각 머리행에 단위를 쓰고 캡션에 반복하지 않는다 | 원고 |

## 그림
| 항목 | 규칙 | 적용 |
|---|---|---|
| 틀 | 1열 2행 테두리 표: 윗칸 그림, 아랫칸 `Fig.1 - 캡션` (보통 굵기, 가운데). 틀은 본문 폭, 사진은 아래 크기 상한 안에서 비율 유지 | docx_post.py |
| 회로도 | `circuit_kit`으로 새로 그린다. 게이트 이름은 몸체 정중앙, 노드 이름은 점 바로 옆 | figures.md |
| 그래프 | 막대는 계열 순서대로 빈 막대 → 검은 막대 → 빗금 | figures.md |
| 참조 | 본문에서 `Fig.1`, `Table.1` | build.py |
| 뒤 간격 | 그림 틀 뒤에 실제 빈 문단(`Figure Spacer`, 12 pt) 정확히 하나. 여백 늘리기로 대신하지 않고, 연속 그림에서도 겹치지 않는다 | style.yaml `spacing.figure_after`, docx_post.py |

코드·명령 창 사진의 `line-px=N`은 원본의 줄 기준선 간격(px)이다. `screenshots.line_pitch_pt`(기본 10.5 pt)에 맞춰 사진 폭을 계산하므로 서로 다른 자르기·확대율에서도 글자 크기가 같다. 상한을 넘으면 개별 축소 대신 여백을 자르거나 구간을 나눈다. 그래프에는 적용하지 않는다.

## 쪽 배치
- 문항마다 답 → 근거 그림·식 → 해석이 이어지게. 제목만 앞 쪽 끝에 남거나 "다음과 같다" 뒤의 식이 다음 쪽으로 넘어가지 않게 한다.
- 그림 상한: 가로 140 mm·세로 95 mm, 세로형(높이/폭 ≥ 1.25)은 높이 80 mm. `width=100%`도 이를 넘지 않고, 작은 원본은 키우지 않는다. 그림마다 필요한 크기가 다르다 (보드 사진은 배선, 회로도는 소자 값, 스코프는 화면 숫자가 읽히게). 숫자가 안 읽히면 세부 그림이나 판독 표를 더한다.
- 누락 그림은 초안에 한 줄 표시로만, 설명과 같은 쪽에. 빈 프레임·촬영 지시·파일명을 그림처럼 넣지 않는다. 최종본에는 없어야 한다.
- 긴 표는 쪽을 나누고 머리행을 반복한다 (모든 셀 keepNext 금지). 캡션 keepNext는 명시적으로 false.
- 쪽 수 목표를 두지 않는다. 수동 페이지 나누기보다 그림 크기·문단 순서·표 폭을 먼저 고친다. 마지막 쪽에 그림 하나·두세 줄만 남으면 앞 쪽과 함께 조정한다.
- `quality.py` 자동 검사는 구조 오류 일부만 잡는다. 실제 렌더링 검토를 대신하지 못한다.

## 수식
| 항목 | 규칙 | 적용 |
|---|---|---|
| 형식 | 기호와 계산은 전부 Word 수식 (`$Y_1$`, `$t_{PLH}$`). Word에서 바로 편집할 수 있다 | pandoc |
| 정렬 | 독립 수식(`$$…$$`)은 문단·OMML 모두 가운데 | math_layout.py |
| 첨자 | `CH2−CH1`, `10^{−6}`, `\tan^{-1}`처럼 조각난 첨자·지수는 OMML 묶음으로 감싼다 (이미지로 바꾸지 않는다). 가로 배치와 음수 부호를 렌더링에서 확인 | math_layout.py |
| 세로 공간 | 앞뒤 8 pt (4 pt 미만은 검사 실패), 자동 줄 높이 1.25. 고정 줄 높이를 쓰지 않아 분수·근호·첨자가 잘리지 않게 한다 | math_layout.py |
| 결과 | 계산한 값은 식과 결과를 한 수식에 쓴다: `$t_{PHL} - t_{PLH} = 13.1 - 12.3 = 0.8\ \text{ns}$` | 원고 |
| 공백 | 연산자 간격은 Word 수식 기본값. 텍스트 공백을 강제 삽입하지 않는다. 숫자와 단위 사이는 `\ ` | build.py, style.yaml `math.op_space: false` |
| 곱셈 | `2 \times 13.1` (괄호 `2(13.1)`은 쓰지 않는다) | 원고 |
| 긴 식 | 문장 속에 두지 않고 따로 뺀다. 배치는 writing.md "수식과 문장의 배치" | 원고, proof.py `[수식]` |
| 세움꼴 | 변수만 기울임. 단위(`V/m`, `F/m`)와 함수 이름(`sin`, `sinh`, `sinc`)은 세운다 | build.py (숫자 뒤 단위·함수 이름 자동) |
| 크기 | 문장 속·독립 수식 모두 기준 11 pt. 글자와 구조 제어 속성(분수·괄호·첨자)에 함께 적용하고, 첨자의 자연스러운 축소는 유지 | style.yaml `size.math`, `size.math_display`, docx_post.py |

수식이 폭을 넘으면 글자를 줄이지 말고 일반식 → 대입 → 결과를 여러 독립 수식으로 나눈다. 폭 추정은 잘림을 보증하지 못하니 분수선·괄호·첨자·양끝을 실제 쪽에서 본다. 뷰어마다 다르게 보이면 어느 뷰어 문제인지 구분해서 말한다.
