# 문체

사람이 쓴 실험 보고서처럼 읽혀야 한다. 짧고 구체적으로, 숫자로 말한다.

## 기본
- 평서체. 실제로 한 일은 과거형(`측정하였다`, `연결하였다`), 이론은 현재형(`XOR은 ~이다`), 계산은 `~로 계산된다`.
- 어미를 섞는다. `~였다`, `~이다`, `~된다`, `~확인할 수 있었다`, `~확인할 수 있다`를 고루 쓰고, 같은 어미가 세 문장 넘게 이어지지 않게 한다.
- 한 문장에는 한 가지 사실만. 주어를 구체적으로 쓴다: "출력이 늦었다" → "B = 1일 때 지연이 B = 0보다 14.3 ns 길었다".
- 불확실한 설명은 `~로 보인다`, `~가능성이 크다`를 문단에 한 번만 쓴다.

## 쓰지 않는 표현
| 쓰지 않음 | 대신 |
|---|---|
| "사용자가 ~", "AI", "제공된 자료", "캡처한 화면", "수정 전/후 코드" 같은 작업 과정 | 본인이 쓴 보고서다. 한 일은 주어 없이 "~했다" (빌드가 `[본인 글]`로 막는다) |
| "목표는 세 가지다. 첫째, … 둘째, …" 같은 개수 예고와 서수 나열 | 한두 문장으로 바로 쓴다 |
| "~에 대해 알아보았다", "~라고 할 수 있다" | "~을 측정하였다", "~였다" |
| "따라서", "즉", "또한", "한편"으로 시작하는 문장 연달아 | 접속어는 문단에 한 번 이하 |
| "이는 ~ 때문이다"로 시작하는 문장 연달아 | 원인을 앞 문장에 붙이거나 주어를 바꾼다 |
| "매우", "다양한", "중요한", "성공적으로", "효과적으로" | 수치로 말한다 |
| 한 문장에 괄호 보충 두 개 이상 | 문장을 나눈다 |
| "~의 ~의 ~의", "~를 통해", "~에 있어서" | 동사로 풀어 쓴다 |
| "본 절에서는 ~을 설명한다" 같은 도입 | 바로 답한다 |
| 본문·목록 이름표의 굵은 글씨, 따옴표로 용어 강조 | 쓰지 않는다 (굵게는 제목과 절 제목에만) |
| 문항과 상관없는 부연, 같은 말 되풀이, 안 해 본 확인 실험 제안 나열 | 뺀다. 문항 하나에 두세 문단이면 충분하다 |

## 용어
- 음차한 전문 용어는 영어로 쓴다: hazard, glitch, capacitance, transistor, fan-out, slew, threshold, jumper wire, strip.
- 장비 이름과 굳어진 실험 용어는 한글로 쓴다: 오실로스코프, 함수 발생기, 브레드보드, 프로브, 구형파, 지연 시간.
- 소자 특성 기호는 수식으로: $t_{PLH}$, $V_{OL}$, $I_{OL}$.

## 수식과 문장의 배치
- 따로 뺀 수식(`$$…$$`)은 **완결된 문장 뒤에** 둔다. 결론까지 말한 문장을 먼저 쓰고, 그 아래에 수식을 보인다.
- 수식 다음 줄에서 앞 문장을 이어 쓰지 않는다 (`로, …`, `이다.`로 시작하는 줄 금지). 수식 뒤에는 새 문장으로 시작한다.
- 문장 속 수식(`$…$`)은 기호와 짧은 식만 (`$t \neq 0$`, `$N = 13$`). 분수, `sin(πt)/(πt)` 같은 괄호 나눗셈, 긴 식은 따로 한 줄로 뺀다 (`proof.py`가 `[수식]`으로 잡는다).
- 따로 뺀 줄에는 식 하나, 많아야 둘. `E_x`, `E_y`, `r`, `k`처럼 여러 식이면 줄을 나눈다.

```
측정값은 계산값보다 3.9–6.1 ns 길었다. 이 차이를 경로의 단 수로 나누어 보면, 경로 길이와 관계없이
한 단마다 약 2 ns가 더해졌음을 확인할 수 있었다.

$$\frac{3.9 + 4.3}{2 \times 2} = 2.05\ \text{ns}, \qquad \frac{5.9 + 6.1}{2 \times 3} = 2.00\ \text{ns}$$

차이의 원인은 다음과 같다.
```

## 목록은 이름표로
경우 나누기, 실험 방법, 오차 원인처럼 항목이 나란한 내용은 목록으로 쓰고, 각 항목 머리에 이름표와 쌍점을 붙인다.
이름표는 굵게 하지 않는다. 이름표 뒤는 한두 문장.

경우 나누기:
```
A의 변화가 출력까지 전달되는 경로는 B 값에 따라 달라진다.

- $B = 0$일 때: $Y_1 = 1$, $Y_3 = 1$로 고정되어 $Y = \overline{Y_2} = A$가 된다. …
- $B = 1$일 때: …
```

실험 방법 (번호 + 이름표, 한 단계에 필요한 설정을 문장으로 묶는다):
```
1. 오실로스코프 준비: 프로브를 10x, 채널 coupling을 DC로 두고 Probe Comp 단자로 보정하여 …
2. 회로 연결: 각 IC의 14번 핀에 5 V, 7번 핀에 GND를 연결하였다. …
```

오차 분석 (차이를 먼저 수식으로 보인 뒤 원인 목록):
```
- 단 사이의 부하: XOR 회로에서는 $Y_1$이 N2와 N3 두 게이트를 구동한다. …
- 판독 분해능: B = 0 조건은 1 ns 단위로 읽혀 판독 오차가 ±0.5 ns 정도다. …
```
- 원인마다 데이터가 뒷받침하는지, 크기가 차이를 설명할 만한지 적는다.
- 확인 실험 제안은 꼭 필요할 때만 한 문장.

## 수식 설명
새 식을 쓸 때는 기호의 뜻과 넣을 값을 먼저 문장으로 말하고, 수식은 기호식 → 대입 → 결과를 한 줄에 쓴다.
```
LED 순방향 전압을 $V_F = 2.0\ \text{V}$, 출력 low 전압을 datasheet 전형값 $V_{OL} = 0.35\ \text{V}$로 두면
$Y = 0$일 때의 LED 전류는 다음과 같이 계산된다.

$$I_{LED} = \frac{V_{CC} - V_F - V_{OL}}{R} \approx \frac{5 - 2.0 - 0.35}{330\ \Omega} = 8.0\ \text{mA}$$
```
여러 조건에 같은 식을 쓰면 일반식을 한 줄, 조건별 값을 다음 줄에 둔다 ($\delta = \dots$ 다음 줄에 $\delta_{B=0}, \delta_{B=1}$).

## 반복 줄이기 (AI 티를 없애는 법)
AI가 쓴 글은 같은 틀을 반복해서 티가 난다. 원고를 다 쓰면 `scripts/style_check.py`로 검사하고 (build.py도 자동으로 돌린다), 걸린 곳을 고친다.

| 검사 | 고치는 법 |
|---|---|
| 같은 어미 3문장 연속 | 둘을 한 문장으로 잇거나(`~였고`, `~하여`, `~므로`) 어미를 바꾼다 |
| 같은 말로 시작하는 문장 반복 | 주어를 생략하거나 앞 문장의 목적어를 주어로 쓴다 |
| 접속어로 시작하는 문장 반복 | 접속어를 지우고 연결 어미로 잇는다 |
| 추측 표현이 한 문단에 둘 이상 | 하나만 남긴다 |
| 같은 구절 3번 이상 | 두 번째부터 다른 말로 (`확인할 수 있다` → `알 수 있다`, `가릴 수 있다`) |
| 문장 길이가 고름 | 짧은 문장 하나, 긴 문장 하나를 섞는다 |
| 같은 서술어가 잦음 (`[어휘 반복]`) | 아래 "어휘 바꾸기"대로 뜻에 맞는 말을 고르거나 문장 틀을 바꾼다 |

## 어휘 바꾸기
용어는 고정하고 서술어와 문장 틀을 바꾼다. 같은 서술어는 문단에 두 번까지, 문서 전체로는 1000자에 두 번 안쪽으로 쓴다.

1. 고정하는 말: 전문 용어, 소자·장비 이름, 측정량 이름($t_{PLH}$, 전파 지연), 과목 기호. 한 번 정한 말은 끝까지 같게 쓴다 (전파 지연 → 지연 시간으로 바꾸지 않는다).
2. 바꾸는 말: 서술어(쓰다, 넣다, 길다, 확인하다), 연결 표현(~에 따라), 비교·결론 문장의 틀.
3. 바꾸는 법: 사전식 유의어가 아니라 그 문장에서 실제로 한 동작의 동사를 고른다.

| 자주 겹치는 말 | 문장에 맞춰 고를 말 |
|---|---|
| 쓰다 | 법칙을 적용하다, 값을 대입하다, 게이트가 하나 더 필요하다·든다, "식은 다음과 같다" |
| 넣다 | 신호를 인가하다·가하다, 입력 핀에 연결하다·물리다 |
| 묶다 | 두 입력을 함께 연결하다, (K-map) 네 칸을 한 묶음으로 덮다 |
| 길다·짧다 | 늦다·빠르다, N ns 더 걸리다, 차이가 N ns다, N배 빠르다, 짧은 쪽을 주어로 뒤집기 |
| ~에 따라·따른 | ~마다, ~별, "B가 0일 때와 1일 때", "B를 바꾸면" |
| 확인하다 | 읽다, 맞다, 드러나다, 또는 수치를 바로 말하기 ("차이는 0.2 ns였다") |
| 나타나다·보이다 | 주어와 서술어로 바로 ("지연이 14 ns였다"), "~에 가깝다" |
| 측정하다 | 재다, 읽다, 기록하다 |
| 증가·감소하다 | 늘다·줄다, 커지다·작아지다, 올라가다·내려가다 |

비교가 여러 번 나오면 틀을 돌린다:
```
B = 1일 때가 B = 0보다 14.3 ns 늦었다.        (큰 쪽 주어)
IC 한 개로 만든 회로는 6.4배 빨랐다.          (배율)
두 방향의 차이는 0.2 ns뿐이었다.              (차이를 주어로)
```

바꾸면 뜻이 달라지는 말(전류가 흐르다, LED가 켜지다)은 그대로 쓴다. `style_check.py`가 계속 잡으면 원고에 `<!-- 어휘 허용: 켜다 -->`를 적는다.
사용자 본인 보고서(`style_samples`)가 있으면 거기서 쓴 동사를 먼저 고른다.

그 밖의 요령
- 문단마다 첫 문장은 결과나 결론으로 시작한다. "~에 대해 살펴보면" 같은 도입은 쓰지 않는다.
- 앞 문장의 끝말을 다음 문장의 주어로 받아 흐름을 잇는다 ("… 3 ns 길었다. 그래도 최대값 15 ns 안에는 들어온다.").
- 같은 뜻을 두 번 말하지 않는다. 표에 있는 숫자는 본문에서 가장 중요한 한두 개만 다시 쓴다.
- `profile.yaml`의 `style_samples`(사용자 본인이 쓴 보고서)가 있으면 그 문장 길이와 어미를 기준으로 삼는다.

## 수치와 단위
- 숫자와 단위 사이는 띄운다 (`5 V`, `9.2 ns`, `330 Ω`). 퍼센트만 붙인다 (`12%`).
- 범위는 en dash (`4.1–5.1 ns`), 전이 방향은 화살표 (`0→1`).
- 계산은 표에 적힌 반올림 값으로 한다. 읽는 사람이 다시 계산해도 같은 값이 나와야 한다.
- 보수는 오버라인 $\overline{A}$. A' 표기는 쓰지 않는다.
