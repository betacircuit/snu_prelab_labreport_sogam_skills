# 기전연 원고와 영어 주석

## 영어 주석
- 과제 공지대로 영어를 쓴다. 필요한 블록의 목적, 경계조건, 단위, 멈춤 조건을 짧게 설명한다. `% fixed electrode`, `% skip boundary nodes`, `% save the tenth sweep`처럼 그 코드에 맞는 구절이면 충분하다.
- 완결된 문장이 더 명확할 때는 써도 된다. 대문자·마침표만 보고 주석을 나쁘다고 판단하거나, 모든 주석을 기계적으로 소문자로 바꾸지 않는다.
- 코드에서 바로 보이는 대입·plot 동작을 매 줄 번역하지 않는다. 주석을 절반 지우는 식의 개수 목표도 두지 않는다. 문제마다 필요한 영어 주석은 남긴다.
- `original blue and red colors`, `as requested`, `according to the prompt` 같은 작업 대화는 결과물에 넣지 않는다. 색상 자체가 과제 조건이면 `% particle 1: blue, particle 2: red`처럼 그 조건만 쓴다. `original data`처럼 실제 의미가 있는 단어는 금지하지 않는다.
- 주석을 고칠 때 문자열 속 `%`(예: `fprintf('%.3f', value)`)나 실행 코드를 주석으로 오인하지 않는다. 수정 후 저장·재실행하고, 저장한 최종 코드 화면을 다시 촬영한다.

## 한국어 본문
- 이번 실행에서 얻은 결과를 먼저 쓴다. 방법 비교는 실제 반복 횟수·오차·그래프 차이를 근거로 한두 문장으로 쓴다. 데이터가 없는 일반적인 장단점을 대칭으로 덧붙이지 않는다.
- 코드 설명은 식, 경계조건, 갱신 순서처럼 결과를 이해하는 데 필요한 내용만 남긴다. `log`가 자연로그라는 문법 해설이나 한 줄씩 번역한 설명은 과제가 묻거나 혼동 가능성이 있을 때만 쓴다.
- 반복마다 초기값을 되돌리는 이유 등 중요한 선택은 짧게 설명한다. 예: `시간 간격은 1 s부터 절반씩 줄였다.` 수치는 실제 코드와 결과에 맞춘다.
- 한계·주의 사항은 문제에서 요구하거나 결론의 의미를 바꾸는 경우에만 간단히 쓴다. 예: `7초 시점의 위치를 비교했다.` 수렴하지 않은 결과를 수렴했다고 쓰거나, 정확성에 필요한 조건을 삭제하지 않는다.
- 마지막에 어디에나 붙일 수 있는 일반론·감상·추가 실험 제안을 덧붙이지 않는다. 자연스러움을 위해 오타, 허위 경험, 확인하지 않은 결과를 넣지 않는다.

## 표기와 확인
- 본문·절 제목·캡션에서는 ASCII `-`를 쓴다: `Newton-Raphson`, `-0.25 V`. 범위는 `0-2 V` 또는 `0 V부터 2 V까지`. 공통 writing.md의 en dash 선호보다 이 과목 규칙이 우선한다.
- `$...$`, `$$...$$`의 마이너스·수학 기호, 링크 주소·파일명·코드는 일괄 치환하지 않는다. 수식은 기존 Word 수식 서식을 유지한다.
- `hw_style.py`는 본문 표기와 일부 작업 맥락을 찾는 검사다. 문체의 자연스러움이나 작성 주체를 판정하는 도구가 아니다. 표기 검사를 통과해도 과제 문항, 코드, 실행 결과와 대조하며 직접 읽는다.
- 코드 사진의 같은 글자 크기, 컬러 보존, 수식 크기, 제출 ZIP 규칙은 기존 스킬대로 유지한다.
