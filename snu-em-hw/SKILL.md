# 기초전자기학 및 연습(기전연) — MATLAB 과제

실험 보고서가 아니라 과제다. 내는 것은 보고서 PDF와 `HW1.m`을 묶은 zip 하나 (규칙은 `references/course.md`).
공통 엔진 `../snu-report-core/SKILL.md`를 먼저 읽는다. 서식·문체·검사·빌드·전달은 엔진 것이고, 아래는 이 과목에서 다른 점이다.

## 어기면 안 되는 것 (사용자 지정)
1. **본인이 올린 사진을 쓴다.** 문제마다 코드 화면 사진과 결과 사진을 **올라온 것 전부, 컬러 그대로** 넣는다.
   - 코드 사진을 넣을지 묻거나, 결과 사진만 넣자고 추천하지 않는다. 사진을 "수정 전", "원본" 같은 말로 분류하지 않는다.
   - 같은 문제 사진이 다시 오면 새 사진으로 바꾼다. 흑백으로 바꾸거나, 다시 그리거나, 코드를 실행해 만든 그림으로 대신하지 않는다.
2. **코드를 글자로 넣지 않고, 쓰거나 고치지 않는다.** 보고서의 코드는 화면 사진뿐이다 (빌드가 코드 블록을 막는다). `HW1.m`은 받은 그대로 zip에 넣는다. 문제가 보이면 채팅으로 알리고 본인이 고친 사진·파일을 기다린다.
3. **본인이 쓴 글로.** "사용자", "AI", "제공된", "캡처", "수정 전/후", "원본 코드"를 쓰지 않는다 (빌드가 `[본인 글]`로 막는다). 캡션은 "문제 1 코드", "문제 1 결과"처럼 짧게 쓴다.
4. **수식은 짧게, 긴 식은 줄을 바꿔서** (아래 "수식").

## 작업 순서
1. **준비와 사진 요청** — `python $E/setup_profile.py --check --course em` (조는 묻지 않는다). 실습 PDF에서 문제 수를 확인하고, 이름·학번을 물을 때 사진도 **한 번에** 요청한다:
   ```
   문제마다 MATLAB 화면을 찍어서 올려 줘 (Windows: Win + Shift + S, Mac: Cmd + Shift + 4).
   - 코드: 편집기에서 그 문제 부분 전체 (줄 번호·주석 보이게, 길면 여러 장)
   - 결과: figure 창 전체, 값을 출력했으면 명령 창도
   - 제출할 HW1.m 파일
   문제: 1) …  2) …  3) …
   ```
2. **자료** — `python $E/ingest.py` → `courses/em/hw01/` (`materials/`, 사진은 `figs/`, `.m`은 `code/`). `requirements.md`에 문제와 **문제별 제약**(내장 sinc 금지, subplot 금지, 그래프 5개 이상, 30x30 행렬 …)을 한 줄씩 적고 `meta.yaml`의 `title`을 채운다.
3. **사진 정리** — 열어 보고 `p1_code.png`, `p1_result.png`, 여러 장이면 `p1_code_2.png`로 이름을 바꾼다. 빠진 사진은 모아서 한 번에 요청한다. 흐리거나 잘렸으면 다시 찍어 달라고 한다.
4. **코드 검사 (고치지 않는다)** — `python $E/mcode.py check code/HW1.m --problems 1 2 3 --forbid "1:sinc,subplot"`. 사진으로도 제약을 대조한다 (곡선 수, subplot 여부). 걸린 것은 "문제 1: 간격이 한 가지라 '5개 이상' 조건에 안 맞음"처럼 채팅으로 알린다. 사진 속 코드와 `HW1.m`이 다르면 어느 쪽이 최종인지 묻고, 최종 코드의 사진을 쓴다.
5. **원고 `hw.md`** (`templates/hw.md`) — 문제마다 `# 1. 함수 그래프`처럼 번호와 짧은 내용 제목을 쓴다 (`Problem 1)` 금지): 풀이 방법(식) → 코드 사진 → 코드 동작 원리 → 결과 사진 → 해석과 문제가 요구한 서술.
   - 사진이 오기 전에도 끝까지 쓴다. 사진 자리는 `hint`로 두고(초안에 한 줄 누락 표시), 사진을 봐야 정할 문장은 `[확인 필요: …]`(노란 형광펜)로 둔다.
   - 동작 원리: 사진 속 코드·주석대로 계산 순서와 이유를 본인이 설명하듯 쓴다. 줄마다 읽어 주거나 코드에 없는 동작을 지어내지 않는다. 주제별 틀은 `references/topics.md`.
   - 수치: 아래 "결과 사진 판독".
6. **빌드·전달** — `python $E/build.py courses/em/hw01 hw --pdf`, 사진과 `HW1.m`이 다 오면 `requirements.yaml`(`scope.hw`, `kind: hw`)을 채워 `--final`. 이후 엔진 SKILL.md의 전달 순서(render → 전 쪽 확인 → review → deliver)를 거치면 `out/em/`에 DOCX·PDF·`HW1.m`·zip이 생긴다. 누락 표시나 `[확인 필요]`가 남으면 zip을 만들지 않는다. 렌더링이 안 되고 사용자가 Word에서 PDF를 만들면 `mcode.py pack … --pdf <PDF>`.

## 결과 사진 판독
- 사진마다 figure 번호, 축 이름·범위·눈금, 곡선 수와 범례, subplot 배치를 먼저 확인하고 과제 조건과 맞는지 본다.
- 값은 눈금 간격의 절반까지만 읽고 "약"을 붙인다. 명령 창 숫자는 그대로 쓴다.
- 이론과 맞춰 본다 (`references/topics.md`의 "확인할 것"). 다르면 사진을 다시 보고, 그래도 다르면 차이와 원인을 쓴다.
- `HW1.m`과 MATLAB·Octave가 있으면 `python $E/mcode.py run code/HW1.m` → `code/figdata.txt`(축 범위, 곡선별 극값)로 판독값을 대조한다. 실행 결과는 대조용이고 보고서에는 사진의 값만 쓴다.

## 제목과 코드 사진 크기
- 첫 제목은 과목명 / `실습 N 결과보고서` / 학번·이름. 임의로 긴 부제를 덧붙이지 않는다.
- 절 제목은 `1. 함수 그래프`, `2. 근 찾기 방법 비교`처럼 간단히. 원문 문제 번호는 requirements.yaml에서 대응한다.
- 코드·명령 창 사진은 같은 너비로 확대하지 않는다. 사진 속 여러 줄의 기준선 간격을 재어 `line-px`에 원본 픽셀 간격을 적는다: `{#fig:p1code line-px=24}`. 공통 `screenshots.line_pitch_pt: 10.5`가 실제 글자 크기를 맞춘다. 다른 확대율로 찍은 사진은 그 사진에서 측정한 값을 쓴다.
- 코드 줄·주석을 보존하고 불필요한 주변 여백만 자른다. 같은 배율에서 크기 상한을 넘으면 사진을 구간별로 나누며, 한 장만 작게 축소하지 않는다. 그래프에는 `line-px`를 쓰지 않는다.
- 수치를 추측해 `line-px`를 넣지 않는다. 사진을 연 뒤 여러 줄의 간격으로 확인하고, 최종 PDF에서 서로 다른 문제의 글자 크기를 비교한다.

## 수식
문장 속 수식은 기호와 짧은 식만. 분수·괄호 나눗셈·긴 식은 문장을 끝내고 다음 줄 `$$…$$`로, 한 줄에 식 하나(많아야 둘). 여러 성분 식(`E_x`, `E_y`, `r`, `k`)은 줄을 나눈다.
```
정규화 sinc 함수는 다음과 같다.

$$\operatorname{sinc}(t) = \frac{\sin(\pi t)}{\pi t} \quad (t \neq 0)$$

$$\operatorname{sinc}(0) = 1$$
```
단위(`\ \mathrm{V/m}`)와 함수 이름(`\sin`, `\operatorname{sinc}`)은 세움꼴이고, 본문과 독립 수식 모두 기본 11 pt Cambria Math로 맞춘다. 분수선·괄호·첨자 구조에도 같은 기준 크기를 적용하고, 연산자 사이에 텍스트 공백을 강제로 넣지 않는다. 첨자의 자연스러운 축소는 유지한다. 수치 결과는 수식보다 짧은 문장으로.
